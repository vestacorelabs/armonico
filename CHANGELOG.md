# Changelog

## 1.0

The first public release, under the name Armonico. Earlier versions ran in the Vesta Core Labs home lab as vestacore-piano and were never published.

- Home Assistant is set up by the installer. One access token from the Home Assistant profile page is all it needs: it installs and starts the Mosquitto app, makes the piano's user, and adds the sensors (MQTT discovery), the helpers, the automations and the blueprints over Home Assistant's API. No file is copied, `configuration.yaml` is not touched and nothing restarts. The token is typed with no echo, kept in memory and never saved. Declining it opens a step-by-step page with an "Open Home Assistant" button for each step.
- Telegram can be set up from the installer, or later with `armonico telegram`: after the bot is made in BotFather, it checks the token, sets the description, the commands (English and Hebrew) and the picture, finds the chat, adds the Telegram bot integration and the allowed chat to Home Assistant, and sends a test message. It asks before each step, and prints the detailed manual way for any step declined or refused.
- The lesson screen starts in English on every device that has not chosen a language, including the screen that asks for the code. It used to flip to Hebrew after the code when the piano had been saved in Hebrew, and part of the page changed language late. The flag menu changes it from then on, and the choice is kept in that browser. The setup screen no longer saves its own page language as the piano's language.
- The touch status screen has a language button of its own in the top bar, English first, with every text, the page direction and the swipe following it. The choice is kept on the device, and `?lang=he` or `?lang=en` sets it.
- Removing the program prints what stays in Home Assistant and where to delete it. `--uninstall` and `--purge` both clear the piano's retained messages and the sensors it announced to Home Assistant from the broker, so the device goes from Home Assistant by itself.
- The footer shows the version on the first visit. It is in the page itself, so a screen that has not entered the code yet shows it, and it survives a change of language.
- The installer's Home Assistant step shows each line as it finishes, with the reason when something is refused: the Supervisor's login cache is cleared before every attempt, the MQTT integration is added with the settings that Home Assistant 2026.9 requires, and the sensors get the entity ids the automations use (`sensor.piano_status` and the rest).
- The piano's own Home Assistant user is `armonicopiano`, made for it and not an administrator. A user that already exists is never changed.
- The Home Assistant files are two levels less deep: `home-assistant/piano.yaml` and three `blueprint_*.yaml` next to it, instead of `packages/` and `blueprints/automation/`.
- The status screen tries the websockets port 1884 of Home Assistant's Mosquitto app as well as 9001, and the installer opens 1884 on that app.
- A touch status screen for a 5-inch display (`screen/piano-status.html`): status, playback, practice and system screens with big stop buttons. See [docs/screen.md](docs/screen.md). The local broker also listens on port 9001 for websockets, and an update adds that listener to a broker this program installed earlier.
- A new name, logo and look: the lesson screen, the setup screen, the terminal and the repository images.
- The `armonico` command. The Telegram commands work from a terminal (status, play, songs, stop, shortcuts, lessons, getmidi, profiles, the screen code), along with update, restart, logs, unstick, reconfigure, uninstall and purge. Members of the `armonico` group run the piano commands without `sudo`.
- An optional MQTT recorder that writes every message of every topic to one file per day (`sudo armonico record on`).
- `--uninstall` leaves nothing behind: the settings, the songs, the recordings, the progress, the shortcuts and the service user go with the program, and the folder the project was unpacked in is removed last, with whatever else was put in it, also when the removal runs through the `armonico` command (the folder is recorded at install). That folder is left alone only when it is a system folder, a home folder, one of your own folders such as Desktop or Documents, or a git checkout with changes that were never committed. `--purge` is the step beyond it: the system packages and Mosquitto.
- `--purge` removes the system packages the installer added, and nothing that was there before.
- `/pianocode` works in Telegram. Home Assistant used to drop it.
- The installer shows the logo, and the lesson screen has a banner that fits phones, tablets and large screens.
- The lesson screen asks for a code, and does so by default. A device enters six digits once and keeps a signed pass for 14 days, renewed every time the screen is used. Reads are behind it too, so the practice history and the backup are not open to the network. The code is shown at the end of the install, by `armonico code` and by `/pianocode`. The screen's settings can turn asking off, draw a new code, and sign every screen out at once, which ends every pass already handed out.
- Three MQTT commands, the ones that hand out the screen code, open the editing tools or change the active profile, answer only to a request carrying the secret in `config.env`. A broker cannot be relied on to say who may publish what, and Home Assistant's Mosquitto add-on does not enforce topic rules at all in series 7.
- The installer offers two clearly separate paths for the broker. When it installs Mosquitto it writes the rules too: the piano reads and writes only under `piano/`, the recorder reads everything and writes nothing, port 1883 stays on the machine, and only the status screen's websockets port (9001) answers on the network, with a login. When the broker is someone else's, the installer says plainly that the rules there are not its to make.
- The setup screen runs as the `armonico` user rather than as root, and hands its answers back through a folder of its own. The installer, which does need root, is what writes `config.env`.
- A release is checked against the `SHA256SUMS` published with it before anything in it runs, and one published without a checksum is not installed. `setup/make-release.sh` builds both files.
- Wording edited on the screen keeps its HTML and loses anything that can execute, checked when it is saved rather than when it is drawn.
- A download follows a redirect only back into the archives it is allowed to reach; a recording is named at random rather than by the clock; the replay route takes a name and not a path.
- The documentation was rewritten, and `SCREEN_CODE` is documented.
- Five color sets on the lesson screen (⚙), kept per profile. They move the page, the cards and the footer; the banner, the seven key colors and the gold key stay as they are.
- The recordings list is read in numbered pages, and the screen is sent 40 of them instead of 8.
- The menu marks the part that holds most of the screen, and marks nothing at the head of the page, where the banner carries the name instead of the menu.
- A lower banner, the About page's credits set apart from the story, one margin width for the whole "How a lesson works" part, and the toolbar above the keyboard stays on one line.
- The logo in the header is the house and the name side by side, so in Hebrew the house sits on the right.
- Searching the free archives from the screen or Telegram answered "no archive answered" every time: the search pages were refused by the check meant for downloads.
- A recording of a lesson with a Hebrew title was saved as a 14 byte MIDI file that no player opens. The markers inside are plain English now, a damaged recording is rebuilt from its events when it is downloaded, and a download with a Hebrew name works.
- The band no longer starts before the first key of a run. An arrangement that plays a whole verse before its melody track enters (a minute of music in one song) used to play it at the start; now only the instrument settings are kept and the band comes in with the player.
- In a lesson, not pressing a key for a while is no longer counted as a mistake. The end of a lesson says the full run is done instead of sitting silent for four seconds, and a lesson stopped by an unplugged keyboard says so in the summary.
- A backup holds the profile that is signed in and the shared songs, and is named after the profile, also when the name is Hebrew. "Restore from a backup" (in the settings, above them) accepts only a backup made by Armonico and refuses anything else before it is kept. It goes back into the profile it was made from, which becomes the profile at the piano; a deleted profile is created again, and a locked one asks for its PIN. Downloads are saved from the page itself.
- The look of the screen (theme, colour set, sound and text size) is saved per profile and applied at once, in the same window, when profiles are switched. A profile that never chose one gets the default (the blue colour set, the grand piano, normal size). A browser that remembers the language of an earlier install starts clean after a new install. On the status screen the theme card shows the theme that is on.
- The status screen's websockets port (9001) answers on the network, and the question about sharing the broker is gone. The setup screen always asks for the screen code (turning it off is `armonico code off`), starts in English, shows the Home Assistant steps only when Home Assistant is used, and shows a broker installed during the setup as found.
- Home Assistant that mDNS cannot find can be typed in during the install, with notes about VLANs and firewalls.
- The person who installs is added to the `armonico`, `adm` and `systemd-journal` groups, the end of the install says how to use them at once, and `armonico` commands that need root ask sudo by themselves.
- Home Assistant and Telegram can be refreshed by updates: the installer asks once whether to keep the tokens (in `/etc/armonico/secrets.env`, root only). With them, an update refreshes the Home Assistant package and blueprints and the bot's profile; a piano automation you changed is first saved as a file in `/etc/armonico/ha-backup/`. Without them, `sudo armonico integrations` asks for new ones, and `sudo armonico forget-tokens` deletes them.
- The "alarm stopped" automation reacts to a person stopping the alarm, not to the bridge restarting or the keyboard being switched off, and the alarm blueprint keeps retrying when the keyboard was lost.
